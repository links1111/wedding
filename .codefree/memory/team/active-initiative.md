婚礼请柬系统当前工作流与待办事项：
1. 编辑页面和管理页面右上角的“查看请柬”按钮已修复跳转逻辑：管理后台通过 /admin/{admin_token} 访问，必须从 /api/a/:token/meta 接口返回数据中的 token 字段获取真正的请柬 token，并构建跳转链接 /w/{WEDDING_TOKEN}，避免跳转后页面为空。跳转逻辑需与总览页面预览按钮保持一致，禁止直接使用路径中的 admin_token 作为请柬 token。
2. 设置页面布局已重构为左右分栏结构：左侧为时间轴样式卡片列表（宽度 220px），垂直渐变金线作为时间轴主干，节点为圆点，主请柬节点更大更亮，选中节点高亮发光，节点右侧显示卡片标题和类型标签，每个子卡片节点右侧放置上移（↑）、下移（↓）、删除（×）图标按钮，无文字。右侧内容区分为上部预览栏和下部设置表单。
3. 预览栏逻辑：主请柬编辑时显示主请柬完整预览（调用 renderMainCardPreview），子卡片编辑时显示对应子卡片预览（调用 renderCardPreview）。子卡片编辑时预览栏显示，主请柬编辑时预览栏也显示。
4. 子卡片需针对 8 种类型（相遇、心动、约会、表白、在一起、旅行、求婚、订婚）分别设计独立视觉装饰，避免简单重复。
5. 卡片预览尺寸需与 index.html 中实际卡片保持一致（max-width: 460px），桌面端预览栏宽度需足够容纳完整卡片（预览栏宽度 492px），避免留白或比例失真。
6. 轮播图切换需实现平滑交叉淡入淡出效果：滚动到新卡片时，旧图片淡出的同时新图片第一张淡入，不等待预加载完成，过渡时间 0.8 秒。切换后轮播图需自动继续播放。
7. 音乐播放需支持用户交互后自动恢复：每次用户点击页面任意位置（除特定区域外）均尝试恢复有声播放，解决浏览器自动播放策略限制。当用户主动点击音乐按钮关闭音乐后，点击页面不再自动播放；再次点击音乐按钮后，点击页面恢复自动播放逻辑。
8. 整体配色方案已确定为莫兰迪粉 + 灰蓝绿法式轻奢风格：主色干枯玫瑰粉 (#d4a5a5)，辅助色灰蓝绿 (#84a59d)，背景暖灰白 (#faf7f5)，文字深灰褐 (#4a403a)，点缀香槟金 (#c9a96e)。
9. 每次代码修改后必须执行 git commit。
10. 修改前务必仔细排查问题根因，一次性修改正确，不要急于修改。对“桌面端空间有限”这类错误假设非常不满，要求认真对待用户的明确指令（如“保持和 index 一致”）。
