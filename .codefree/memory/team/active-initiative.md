婚礼请柬系统当前工作流与待办事项：
1. 编辑页面和管理页面右上角的"查看请柬"按钮已修复跳转逻辑：管理后台通过 /admin/{admin_token} 访问，必须从 /api/a/:token/meta 接口返回数据中的 token 字段获取真正的请柬 token，并构建跳转链接 /w/{WEDDING_TOKEN}，禁止直接使用路径中的 admin_token 作为请柬 token。
2. 设置页面布局已重构为左右分栏结构：左侧为时间轴样式卡片列表（宽度 220px），垂直渐变金线作为时间轴主干，节点为圆点，主请柬节点更大更亮，选中节点高亮发光，节点右侧显示卡片标题和类型标签，每个子卡片节点右侧放置上移（↑）、下移（↓）、删除（×）图标按钮，无文字。右侧内容区分为上部预览栏和下部设置表单。
3. 预览栏逻辑：主请柬编辑时显示主请柬完整预览（调用 renderMainCardPreview），子卡片编辑时显示对应子卡片预览（调用 renderCardPreview）。主请柬和子卡片编辑时预览栏均显示。
4. 子卡片需针对 8 种类型（相遇、心动、约会、表白、在一起、旅行、求婚、订婚）分别设计独立视觉装饰，避免简单重复。
5. 卡片预览尺寸需与 index.html 中实际卡片保持一致（max-width: 460px），桌面端预览栏宽度需足够容纳完整卡片（预览栏宽度 492px），避免留白或比例失真。禁止以"桌面端空间有限"为由缩小预览区。
6. 轮播图切换需实现平滑交叉淡入淡出效果：滚动到新卡片时，旧图片淡出的同时新图片第一张淡入，不等待预加载完成，过渡时间 0.8 秒。切换后轮播图需自动继续播放。已修复 carShow 函数中索引计算错误和 performFadeSwitch 中 inline style opacity 覆盖 CSS class 导致 active 类切换失效的问题。
7. 音乐播放需支持用户交互后自动恢复：每次用户点击页面任意位置（除音乐按钮和回执表单区域外）均尝试恢复有声播放，解决浏览器自动播放策略限制。当用户主动点击音乐按钮关闭音乐后，点击页面不再自动播放；再次点击音乐按钮后，点击页面恢复自动播放逻辑。已引入 musicClosed 状态区分"主动关闭"与"暂停"。
8. 整体配色方案已确定为莫兰迪粉 + 灰蓝绿法式轻奢风格：主色干枯玫瑰粉 (#d4a5a5)，辅助色灰蓝绿 (#84a59d)，背景暖灰白 (#faf7f5)，文字深灰褐 (#4a403a)，点缀香槟金 (#c9a96e)。禁止使用灰色、红色等俗气配色。
9. 每次代码修改后必须执行 git commit。
10. 修改前务必仔细排查问题根因，完整阅读相关代码和布局层级后再动手，一次性修改正确。禁止以"桌面端空间有限"等错误假设为由偏离用户明确指令（如"保持和 index 一致"）。修改后需自行验证逻辑正确性。
11. 轮播图自动播放间隔已调整为 4 秒。
12. 顶部提示文案已改为"长按看清文字"。
13. 音乐按钮样式已优化为优雅圆环设计，播放中时按钮整体缓慢旋转。
