用户要求：每次修改代码后必须 git commit。修改前务必仔细排查问题根因，完整阅读相关代码和布局层级后再动手，一次性修改正确，强调错误修改会导致严重事故，不要急于修改。修改后需自行验证逻辑正确性，不能只改不验。用户对"桌面端空间有限"这类错误假设非常不满，要求认真对待用户的明确指令（如"保持和 index 一致"）。用户对反复修改同一问题仍不生效非常不满，要求改完务必自己检查验证好。
